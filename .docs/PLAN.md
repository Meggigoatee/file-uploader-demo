# 범위와 6시간 실행 계획

상태: 2026-10-22 **수정 계획 승인, S0~S6 구현/회귀와 S8 배포·원격 검증 완료**. S7 옵션은 핵심 검증·배포를 우선해 생략했다. Vue 3 + TypeScript + Vite / Workers + D1 + 비공개 R2를 구현했다. 설치 버전은 유지했다. 사용자 로그인/R2 활성화 후 실제 원격 바이트와 공개 URL을 확인했다. [실제 루프](./TDD_LOG.md), [실행 결과](./VALIDATION.md), [실행 방법](./README.md#로컬-실행)을 따른다.

## 목표의 정의와 완료 기준

2026-10-22 후속 UI-R01: 사용자 요청1~4번(업로드 위/정책 아래, 추가·등록 확인 입력 분리, 정책 새로고침, 행별 업로드)을 구현·배포했다. 사용자5번은 의견 요청으로, AI의 수동 성공 항목 비우기 권고를 미합의 제안으로 남겼다. 아직 자동/일괄 정리를 구현하지 않았다. 최신 결과는 VALIDATION/TDD_LOG의 UI-R01이다.

2026-10-21 사용자 보강 정의를 기준으로 아래처럼 구분한다.

- **필수 목표**: 과제가 요구하는 반드시 구현되어야 하는 기능.
- **핵심 추가 기능**: 과제 수행자가 기술적 완성도 및 UX를 향상시키기 위해 제시한, 필수 목표 외의 구현 목표.
- **개발·제출 작업**: 검증, 배포, 문서·기록 등 과제를 완성하고 제출하기 위한 작업. 기능 목표와 별도로 관리한다. 필수 제출 조건은 여전히 충족해야 한다.
- **P0/P1**: 구현 순서와 시간 배분을 위한 우선순위이다. 요구사항의 출처나 필수 여부, 상호 합의 여부를 뜻하지 않는다. 추가 기능은 양쪽이 같은 범위를 합당하다고 판단한 뒤에만 최종 계획에 포함한다.

정책을 DB에 저장하고, 서버가 그 정책으로 실제 파일 업로드를 허용·거부하는 공개 데모를 완성한다. 필수 목표와 필수 제출 조건을 모두 충족해야 과제의 최소 완료이다. 선택한 핵심 추가 기능은 별도로 구현·검증 상태를 기록한다. 화면만 완성하거나 파일을 저장하지 않고 성공 응답만 반환해서는 완료가 아니다. 화면 배치와 조작·상태는 [UI_UX.md](./UI_UX.md), 기술·저장 흐름은 [DESIGN.md](./DESIGN.md)를 기준으로 한다.

## 범위 제한

- 확정 범위는 위 필수/핵심 추가 기능 및 품질 기준, 카테고리 기능의 조건부 구현, 필수 제출 조건과 기록 규칙이다. 서버의 정책 강제는 필수 B1의 구현 방법이며 자동 검증은 Q1에서 관리한다.
- 새 제안은 별도 합의 후 갱신한다. 이전 A/B 시간 수치는 미검증 추정으로 계속 사용을 보류한다. 실패를 성공으로 추정하는 상태 조회·자동 재시도는 넣지 않는다.
- 현 단계 대안/범위 밖: 로그인/역할, 사용자별 정책, 감사 테이블, 저장된 파일 목록/미리보기/다운로드/삭제 화면, 대용량 분할·재개, 바이러스 검사, 압축 해제, 실시간 동기화, 완전한 화이트리스트, 전용 모니터링 화면. 업로드 전 대기 목록은 저장된 파일 목록 화면과 구분해 논의한다.
- 제외할 구조: ORM, 범용 Repository/Service 계층, 공통 CRUD 프레임워크, DI 컨테이너, 상태관리 라이브러리, 모노레포. 한 화면에 Vue Router도 필요하지 않다.

R2 사용이 어렵다면 파일 저장 대안을 먼저 결정한다. Express + SQLite + 영속 디스크가 있는 Node 호스팅은 대안이지만, Cloudflare와 별도 호스팅을 함께 도입하지 않는다. R2가 없다는 이유로 파일을 메모리에만 두거나 성공 응답만 반환하지 않는다. 비용이 발생하는 구독은 사용자 계정의 선택이 필요하다.

## 약 6시간 내 실행 순서와 판단 기준

문서·구현·검증·배포를 포함한 전체 작업 예산은 약 360분이다. 이미 진행한 준비·논의 시간과 구현 시작 시점을 함께 기록하고 실제 남은 시간을 확인한다. 아래 순서는 최신 TDD 실행안의 요약이며 세부 테스트·종료 조건은 TDD_PLAN을 따른다. 단계별 소요 시간의 실측 견적은 아니다. 과거 단일 파일 기준 배분과 A/B 수치는 현재 범위의 시간 근거로 사용하지 않는다.

| 순서 | 작업 | 다음 단계로 넘어갈 조건 |
| --- | --- | --- |
| 시작 조건 | TDD 계획 승인·준비사항 확인 | 사용자 승인, Cloudflare/GitHub 권한과 R2 조건·실제 남은 시간 확인 |
| S0 | 최소 실행·테스트 구성 | Vue/Worker·로컬 바인딩·typecheck/build·실제 계약 검사 실행 가능 |
| S1 | 공유 검증 규칙 | 정규화·이름·토큰·길이 경계 단위 검사 통과 |
| S2 | 정책 DB/API | 초기 7개·즉시 저장·custom 20자/200개/중복·삭제·경쟁을 실제 D1로 확인 |
| S3 | 실제 업로드·예산 | T 판정·수신 한도·예산 예약·R2 바이트/미저장·장애 검증. 준비된 계정의 원격 저장 경로 조기 확인 |
| S4 | 정책 화면 | 정책 영속성/실패 UX, 등록 확인·대표 분류와 API 일치 |
| S5 | 다중 업로드 UX | 선택/드롭/사전 검사/제외·순차 전송·진행/저장 결과·수동 재시도·잠금 확인 |
| S6 | 교차 회귀 | 현재 기능의 단위·실제 바인딩 통합·핵심 E2E와 타입/빌드 통과 |
| S7 | 시간 여유 옵션 | 필수·핵심·검증·제출 시간을 확보한 뒤 필터, 이어서 일괄 변경의 TDD 가능 여부 판단 |
| S8 | 최종 배포·제출 | 원격 DB/R2·공개 접속, 실제 스키마·실행 방법·증거·TDD/AI 기록 완료 |

각 단계 시작/종료와 막힌 원인을 기록해 남은 시간을 다시 판단한다. 옵션은 합의한 핵심 기능보다 먼저 구현하지 않는다. 시간이 밀리면 필수 기능·검증·배포·필수 제출을 유지하고, 핵심 추가 기능의 축소가 필요하면 사용자에게 범위 조정을 알리고 미구현 상태를 명시한다. 동일 원인으로 15분 이상 막히면 원인을 기록하고 작은 대안을 검토한다. 실제 연결이 불가능하면 정적 화면만 확장하지 않고 배포/저장 구성을 재결정한다.

모든 기능 단계는 테스트 선행 → 실제 실패 원인 기록 → 최소 구현 → 리팩토링 → 대상/기존 기능 회귀 확인 순서로 수행했다. 실제 실패/절차 보정과 8개 루프를 TDD_LOG에 기록했다. 현재 핵심 구현/회귀·원격 배포 검증을 완료했다.

후속 사용자 확인에 따라 Cloudflare 실제 운영 장애·계정 한도 응답의 모방 검사는 제외한다. 위 단계의 오류/한도 검증은 TDD_PLAN의 최신 범위(앱 자체 예산·정책 불변식·클라이언트 통신 제어)를 따른다. 실제 제공자 장애 동작을 검증했다고 표시하지 않는다.

## 제출 직전 확인

- [x] 의존성/로컬 상태가 없는 복사본에서 기존 D 전역 스토어만으로 frozen/offline 설치·DB 초기화·타입/빌드를 확인하고 명령을 작성했다. 다른 OS/PC 검증은 아니다.
- [x] 실제 SQL 마이그레이션과 DESIGN의 테이블 정의가 일치한다.
- [x] 새로고침 후 정책이 유지되고 API 직접 호출도 동일한 정책으로 차단된다.
- [x] 정상 파일이 실제로 저장되고 거절 파일은 저장되지 않는다. 바이트/객체 수 증거를 구분했다.
- [x] GitHub 주소와 공개 사이트 URL을 기록했다. Chromium으로 공개 사이트를 열어 검증했다. 이번 Git 커밋/푸시는 미요청으로 하지 않았다.
- [x] `.docs/VALIDATION.md`에 실행 결과, 실패·미구현 항목, 증거 위치가 있다.
- [x] AI 제안에 대한 사용자의 채택·수정·폐기와 실제 검증 결과를 회고에 남겼다.
- [x] 일반 비밀값 패턴 후보0, 로컬 DB/캐시/업로드 파일 Git 제외를 확인했다. 원격 dummy 본문 파일도 비교 후 삭제했다. 실제 개인정보 파일을 사용하지 않았다.
