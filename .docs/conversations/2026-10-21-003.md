# 대화 003 — 사용자 추가 기능 제안과 브레인스토밍

- 날짜/시간대: 2026-10-21, Asia/Seoul.
- 최초 시각 확인: 21:34 KST. 실제 사용자 전송 시각은 제공되지 않음.
- 단계: 추가 기능 제안·비교. 구현 요청 없음.

## 사용자 입력 원문

```text
핵심 추가 기능 추가를 위한 브레인스토밍을 진행한다.

사용자가 제안한 요구, 네가 한 제안을 구분한다. 추가 기능은 서로가 합당하다고 생각한 것만 최종 계획에 포함시키고, 그 외에는 별도 대안으로서 정리한다.

[사용자 제안]

나는 프론트엔드 단의 작업을 상대적으로 더 많이 했고, 사용자 경험으로 녹아나는 기능이 좋은 프로그램으로서 동작한다고 믿는다. 파일 업로드 측면에서는 다음 사항을 고려할 만 하다.

- 다중 파일 선택: 사용자가 여러 파일을 올릴 때 편의성을 향상시킨다.
- 드래그 앤 드롭: 사용자가 별도 선택 창을 거치지 않고 탐색기에서 바로 업로드를 진행할 수 있도록 하여 시간을 단축하고 편의성을 도모한다.
- 파일 별 업로드 진행률과 결과: 진행률이 표시되면 사용자는 작업이 언제 종료될 지 파악하고 대기 시간동안 다른 작업을 계획적으로 수행할 수 있다. 업로드 결과에 따라 다시 업로드를 해야할지 여부를 바로 판단하여 사고를 방지한다.

확장자 정책 및 관리에서는 다음을 고려해보자.

- 확장자 카테고리 필터: 확장자는 최대 200개 까지 등록될 수 있으며, 이를 체크박스로 일렬로 관리하는 것은 직관적인 파악을 방해하고 실수 확률을 높인다. 확장자를 카테고리 필터 별로 묶으면 해당 카테고리 전반 정책을 한 번에 관리할 수 있으며, 파일의 범주(사진/영상/음성/문서 등)을 직관적으로 차단 및 해제할 수 있다.
- 잘 알려진 확장자 카테고리 분류: 확장자에 생소한 업로더는 특정 확장자를 일일히 찾아 등록하는 것이 어려울 수 있다. 잘 알려진 확장자를 미리 분류하여 사전 카테고리에 등록시키면 업로더는 확장자를 모두 알 필요 없이 원하는 파일들을 허용 및 차단 시킬 수 있다.
- 전송 전 확장자 정책 검사: 프론트엔드에서 업로드 한 파일 확장자를 검사하여 업로더에게 업로드 결과를 예측 가능하게 한다. 업로더는 해당 결과를 보고 파일을 수정 및 제외시킬 수 있고, 서버는 불필요한 실패를 방지할 수 있어 효율성이 증가한다.
```

## 입력 의도

체감 UX를 중심으로 추가 기능을 논의한다. 원래 제안자와 AI 세부안을 구분하고, 상호 합의된 동일 범위만 최종 계획에 넣는다. 제안 자체를 구현 지시나 구체 범위의 확정으로 간주하지 않는다.

## AI 중간 응답

> 제안별로 UX 효과와 6시간 내 구현 비용을 비교하겠습니다. 사용자 제안과 제 제안을 구분해 기록하고, 양쪽이 합당하다고 판단한 항목만 최종 계획에 반영하겠습니다. 아직 합의되지 않은 항목은 별도 대안으로 남기겠습니다.

## AI가 요청한 선택 질문

도구: `request_user_input_async`. 요구사항의 비중을 확인하기 위한 질문이며 구현 승인 요청이 아니다.

질문: 카테고리 기능은 조회 필터·대표 확장자 안내와 일괄 차단/해제를 나눠 검토할 수 있습니다. 6시간 범위에서 어느 쪽에 더 비중을 두고 싶으신가요?

선택지:

1. 업로드 UX 우선: 카테고리는 조회·안내부터 검토
2. 정책 관리 우선: 카테고리 일괄 차단/해제까지 검토
3. 두 방향의 구현 범위와 비용을 먼저 비교

사용자는 3번을 선택했다. 이 사용자 메시지와 이후 응답은 [대화 004](./2026-10-21-004.md)에 별도 기록한다. 이번 요청의 최종 비교 답변도 해당 파일에 이어 기록한다.

## 도구·자료 사용

- PowerShell/rg: 기존 PLAN/DESIGN/기록과 현재 제외 범위 확인.
- clock.curr_time: KST 기록 기준 확인.
- web.run: MDN의 다중 파일 선택·드롭·XHR 업로드 진행·대표 파일 형식 자료 확인.
- apply_patch: FEATURE_BRAINSTORM 작성, 최종 계획과 미합의 대안 분리, 문서 연결 수정.
- 별도 스킬·서브에이전트·프로젝트 라이브러리 사용/설치 없음. 앱 코드·테스트·배포 없음.

구체 비용·기능 판단과 작업 결과는 FEATURE_BRAINSTORM 및 PROMPT_LOG의 P003에 기록한다.
