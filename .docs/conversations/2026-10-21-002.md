# 대화 002 — 목표 분류의 정의 보강

- 날짜/시간대: 2026-10-21, Asia/Seoul.
- 최초 시각 확인: 21:12 KST. 사용자 메시지의 실제 전송 시각은 제공되지 않음.
- 단계: 기존 준비 문서의 용어·분류 보완. 코드 구현 요청은 없음.

## 사용자 입력 원문

```text
이전에 내가 말한 내용을 보강한다.
[필수 목표] 란 과제가 요구하는 반드시 구현되어야하는 기능을 맗한다.
[핵심 추가 기능] 이란 과제의 기술적 완성도 및 UX를 향상시킬 목적으로 과제 수행자가 제시한 필수 목표 외의 구현 목표를 말한다.
```

## 입력의 의도와 기존 결과 보완

과제에서 반드시 요구한 기능과 수행자가 완성도·UX를 위해 제안한 기능을 구분하도록 정의했다. 기존 계획에서 P0를 필수 목표로 부르고 일부 추가 기능을 함께 분류한 부분을 수정한다. 기술 스택이나 개별 추가 기능을 승인했다는 의미로 확대 해석하지 않는다.

## AI 중간 응답 1

> 보강한 정의를 문서에 반영하겠습니다. 과제가 요구하는 필수 기능, 완성도·UX를 위한 핵심 추가 기능, 제출 문서를 구분하고 이번 대화도 별도 파일로 기록하겠습니다.

## AI 중간 응답 2

> 기존 문서에서 필수 목표에 섞여 있던 크기·파일명 검증, 오류 UX, 동시성 보완 등을 핵심 추가 기능으로 분리했습니다. P0/P1은 필수 여부와 별개인 우선순위로 정의했고, 설계와 검증표에도 같은 구분을 반영했습니다.

## 도구 사용 및 변경 결과

- `exec_command`/PowerShell/`rg`: 기존 계획·문서·검증표에서 P0/필수/추가 구분과 목표 ID를 확인.
- `clock.curr_time`: 기록 기준 시각 확인. 한국 시간 사용.
- `apply_patch`: `.docs` 문서만 수정하고 이 대화 파일 생성.
- PLAN: 필수 목표 A/B, 핵심 추가 기능 K1~K7, 개발·제출 작업 D/U/Q로 분류. 기존 B4는 K2/K3로 이동하고 A3/A4에 섞인 정규화·고정 등록 거절은 K1로 분리.
- README/DESIGN/CONSIDERATIONS: 사용자 정의와 P0/P1의 의미를 일치시킴. 원본 3번 고려사항은 문서화 대상이며 전부 필수 구현이 아님을 명시.
- VALIDATION: 시나리오별 필수/추가 목표 참조 수정. 추가 기능 제외와 필수 기능 실패를 구분하도록 함.
- 6시간 예산·기술 스택 제안·구체 기능 동작은 이번 분류 수정으로 변경하지 않음. 원본 과제와 이전 대화 원문은 유지.
- 코드/설정/SQL 생성, 패키지 설치, 앱 테스트, 배포 없음. 신규 웹 조사·별도 스킬·서브에이전트 사용 없음.
- 문서 검증 결과: Markdown 9개, 코드 블록을 제외한 로컬 링크 11개(앵커 포함), 깨진 링크 0개, `.docs` 밖 파일 0개, 일정 합계 360분. VALIDATION에 폐기된 B4 참조 0개를 확인했다.

## 판단·회고

- 사용자 보강을 그대로 반영: 필수 목표/핵심 추가 기능의 정의.
- 고쳐 쓴 것: AI의 이전 ‘P0 필수 목표’ 분류. 과제 필수 기능과 수행자 제안이 혼합되어 있었음을 사용자 보강을 계기로 바로잡음.
- 폐기한 해석: 중요하다고 판단한 기능 또는 P0인 기능이 곧 과제 필수라는 해석.
- 이번 보강만으로 기술 구성·개별 추가 기능의 사용자 채택 여부는 확정하지 않음.
