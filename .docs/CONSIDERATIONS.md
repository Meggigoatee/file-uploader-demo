# 고려사항과 판단 근거

상태: 핵심 구현·이전 배포와 후속 세션/카테고리 로컬 구현을 수행했다. 아래 P0/P1은 최초 설계 당시 우선순위이며 현재 구현 여부는 PLAN/TDD_LOG/VALIDATION을 따른다. P0가 과제 필수 목표를 뜻하지 않는다.

카테고리 후속 고려: 필터는 조회만 바꾸며 일괄 차단은 고정·커스텀을 포함해 200개 초과 시 전부 취소한다. 세션별 카테고리와 FK/복합 유일성을 사용한다. 소속 편집/허용/삭제는 D1 batch로 묶어 중간 상태를 남기지 않는다. 사용자 답변대로 카테고리 삭제는 소속 확장자를 허용하므로 다른 카테고리/수동 등록과 겹친 값도 해제됨을 화면에 안내한다. 생성/편집은 정책을 바꾸지 않는다. 파일 삭제·예산 환급·실시간 전파·감사 이력/복원은 추가하지 않았다. 이름30자/구성원50개·기존 JSON4KiB 입력 제한을 적용한다. 상세 범위는 [후속 계획](./CATEGORY_PLAN.md)이다.

사용자 정의에 따라 **과제가 반드시 구현하도록 요구한 기능만 필수 목표**로 분류한다. 이 문서의 원본 3번 고려사항은 판단·근거의 문서화 대상이며 전부 필수 구현 대상은 아니다. 그중 기술적 완성도·UX를 높이려고 수행자가 제안한 구현 목표 K1~K7은 FEATURE_BRAINSTORM의 기존 AI 후보로 보관한다. 이 문서의 P0/P1은 초기 제안 평가이며 상호 합의된 구현 약속이 아니다. 사용자 제안과 신규 AI 제안의 비교·합의는 FEATURE_BRAINSTORM에서 관리한다. 검증·배포·문서화는 개발·제출 작업으로 별도 관리한다.

## 검증·보안

최신 합의와 판정 기준은 DECISIONS를 따른다. 사용자 기능 외 AI-01/02/03/05/06/08 범위를 반영하며 AI-07은 생략, AI-09는 보류한다. 과거 P0/P1 표의 미선택 세부안은 확정 구현 약속이 아니다.

| 고려사항 | 판단 | 이유와 남는 한계 |
| --- | --- | --- |
| 확장자만으로 안전한가 | P0 한계 명시 | 과제의 차단 정책은 구현하되 악성코드 탐지로 설명하지 않는다. 허용 목록 전환은 제외한다. |
| 이름과 실제 내용/시그니처 불일치 | 이번 범위 생략 | 제한적 PNG/JPEG/PDF 검사도 대안 보관. 이번 업로드는 실제 내용 형식·악성 여부를 보증하지 않는다. |
| 대소문자 | P0 | 정책과 파일명 토큰을 ASCII 소문자로 비교해 `.EXE` 우회를 막는다. |
| 이중 확장자·tar.gz | P0 | 첫 이름 부분 이후 토큰 중 차단 항목이 있으면 거절. 복합 확장자 정책 자체는 지원하지 않는다. 문서 버전 이름도 걸릴 수 있음을 안내한다. |
| 확장자 없음·dotfile | P0 거절 | 판정 불명확한 이름과 `.env` 등 민감 파일의 실수 업로드를 줄인다. |
| 긴 이름·한글 이름 | P0 | UTF-8 255바이트. 한글 이름을 허용하지만 문자 수와 바이트 수 차이를 안내한다. |
| 입력의 점·공백·특수문자·유니코드 | P0 | 앞뒤 공백/선행 점 1개만 정규화, 확장자는 ASCII 영숫자 1~20자. 모호한 값은 거절한다. |
| 클라이언트 검증 우회 | P0 | 서버 재검증과 D1 제약. 직접 HTTP 호출을 테스트한다. |
| 크기·개수 및 거짓 Content-Length | P0 | 파일 1개/최대 5 MiB, 전체 본문 6 MiB를 실제 읽으며 제한. 누락·과장/축소 길이 정보에 의존하지 않는다. |
| 경로 조작·원본명 덮어쓰기·실행 | P0 | 위험한 이름 거절 + UUID 키 + 비공개 R2. 서버의 실행 경로에 파일을 놓지 않는다. |
| MIME 스푸핑 | P0 신뢰하지 않음 | 클라이언트 MIME을 허용 근거로 쓰지 않는다. 저장 MIME은 octet-stream. P0는 실제 형식 일치를 보장하지 않는다. |
| SQL injection·파일명 XSS | P0 | 값 바인딩, Vue 텍스트 출력만 사용. v-html/원본명 HTML 삽입을 하지 않는다. |
| 압축 폭탄·이미지 파서 공격 | P0 처리 경로 제거 | 저장만 하고 압축 해제·이미지 파싱을 하지 않는다. 저장된 파일이 안전하다는 의미는 아니다. |
| HTML/SVG 등 활성 콘텐츠 | P0 비공개 | 다운로드·미리보기·공개 R2 URL을 만들지 않는다. 추후 제공 시 별도 출처/attachment/nosniff를 검토한다. |
| 0바이트·손상 multipart·다중 file 필드 | P0 거절 | 성공의 의미를 실제 단일 파일 저장으로 제한한다. |

근거: OWASP는 MIME을 신뢰할 수 없다고 설명하고 파일명 변경·크기 제한·격리 저장 등 다층 대응을 제안한다. 본 과제는 공개 정책 편집 데모로 범위를 줄였으므로 인증과 포괄적 내용 검사는 미구현으로 명시한다. [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) (확인: 2026-10-21).

## 정책·데이터

| 고려사항 | 판단 | 이유와 남는 한계 |
| --- | --- | --- |
| 고정/커스텀 중복 | P0 | 고정 7개는 커스텀으로 추가 불가. unchecked인 exe도 커스텀 입력으로 우회 등록하지 않는다. |
| 20자·200개 근거와 UX | P0 | 원본의 필수 조건. 실제 사용 통계에서 나온 최적값이라고 주장하지 않는다. 길이·개수와 초과 이유를 표시한다. |
| 동일 값 동시 추가 | P0 | 정규화 PK로 하나만 저장. 나머지는 중복 메시지로 재조회한다. |
| 199개 상태에서 서로 다른 값 동시 추가 | P0 | 상한 조건을 포함한 원자적 INSERT. 실제 동시 요청으로 200개 이하를 검증한다. |
| 정책 조회/인덱스 | P0 최소 | 최대 207행을 한 번 읽어 메모리 Set으로 비교. PK 외 인덱스/캐시는 필요하지 않다. |
| 정책 감사 이력 | 제외 | 변경 시각과 구조화 로그만 남긴다. 인증이 없어 ‘누가’를 식별할 수 없고 감사 테이블까지 만들 필요가 작다. |
| 초기화·재배포 | P0 | 새 익명 세션만 fixed7 unchecked/custom0으로 생성한다. 같은 세션의 새로고침·재접속은 DB 값을 유지한다. 기존 전역 정책 값은 복사하지 않는다. |
| 정책 누락/DB 장애 | P0 | 빈 정책으로 취급해 허용하지 않고 503으로 닫는다. |
| 파일 저장과 메타데이터 DB 간 불일치 | 구조 축소 | 작업 상태 테이블·조회 API는 보류. 예산 행은 시도 전 보수적으로 차감하고 환급하지 않으며 파일 성공 상태를 뜻하지 않는다. |
| 기존 파일에 차단 정책 소급 | 제외 | 정책은 앞으로 시도하는 업로드에 적용. 기존 파일 탐색·삭제 기능은 요구 범위를 넘는다. |

## UX·예외

| 고려사항 | 판단 | 이유와 남는 한계 |
| --- | --- | --- |
| 차단 메시지 | P0 | 예: ‘exe 확장자가 차단되어 업로드할 수 없습니다.’ 서버가 판정한 토큰을 표시한다. |
| 로딩/실패/네트워크 단절 | P0 | 초기 재시도, 작업 중 중복 방지, 실패 시 입력 유지. 성공하지 않은 작업을 성공으로 표시하지 않는다. |
| 저장 실패 화면/DB 일치 | P0 | 서버 성공 후 확정. 응답 유실로 결과가 불확실하면 재조회한다. |
| 업로드 실패 후 재시도 | 수동 재시도 채택 | 성공 항목 유지. 응답 유실은 완료 확인 실패로 다루되 서버 미저장으로 단정하지 않는다. 중복 객체·추가 예산 소비 가능성은 남는다. |
| 접근성·반응형 | P0 기본 | label, 실제 button, 키보드 조작, 결과 영역 aria-live, 좁은 화면 줄바꿈. 디자인 시스템은 도입하지 않는다. |
| 브라우저 accept 필터 | 보조 | 사용해도 서버 차단을 대체하지 않는다. 정책으로 선택을 과도하게 제한해 검증 증거를 숨기지 않는다. |

## 운영 및 추가 발견

| 고려사항 | 판단 | 이유와 남는 한계 |
| --- | --- | --- |
| 새로고침·다른 탭 동시 편집 | P0 최소 | 항목별 변경 API, 동일 항목 마지막 커밋 우선, 재조회. 실시간 push·정책 버전 충돌 해결은 제외한다. |
| 검사 중 정책 변경 | P0 기준 정의 | 저장 직전 정책 조회 시점의 스냅샷 적용. 조회 이후의 변경은 진행 중 업로드를 소급 취소하지 않는다. |
| 로그·모니터링 | P0 최소 | requestId/상태/이유/크기/소요 시간으로 추적. 파일 내용·원본명·비밀값을 제외. 알림 시스템은 제외한다. |
| 사용자별 정책·화이트리스트 확장 | 익명 세션별 정책 구현 | 계정/로그인은 추가하지 않는다. 서버 발급 쿠키로 정책을 분리하되 같은 프로필의 탭·쿠키를 공유하는 사람은 같은 세션이다. 계정별 권한·화이트리스트는 제외한다. |
| 공개 데모의 정책 훼손 | 세션 간 격리 | 다른 세션의 정책 CRUD·업로드 판정을 분리한다. 세션 토큰 소유가 접근 기준이며 실제 신원/관리자 권한을 보장하지 않는다. 쿠키 차단/미발급 시 공유 정책으로 우회하지 않는다. |
| 익명 세션 보관·발급 | 최소 구현·한계 명시 | HttpOnly 세션 쿠키, DB에는 토큰 해시만 저장. 서버 TTL·자동 정리·발급 제한은 미구현이라 DB 행 누적/반복 생성 위험이 남는다. 브라우저 복원으로 쿠키가 유지될 수 있다. 요청하지 않은 초기화 UI/스케줄은 만들지 않는다. |
| 공개 업로드의 비용·쿼터 소진 | 앱 전용 누적 예산 | 실제 바이트 상한과 D1 원자적 예산 예약. 계정 전체 비용·가용성은 보장하지 않으며 사용량을 확인한다. |
| cross-origin 변경 요청 | P0 보조 방어 | 명시적으로 다른 Origin은 거절. 직접 API 요청을 막는 인증 수단으로 오해하지 않는다. |
| 보관 기간·개인정보 | P0 안내 | 테스트 파일만 업로드, 1일 만료 제안. 만료 처리는 지연될 수 있다. 공유 데모에 민감 파일을 사용하지 않는다. |
| Worker 임시 저장의 착각 | P0 R2 저장 | 서버리스 메모리/로컬 임시 파일은 영속 저장으로 인정하지 않는다. |
| DB read replica·캐시 지연 | P0 단순화 | 읽기 복제·앱 캐시를 도입하지 않고 저장된 정책을 서버에서 매번 읽는다. |
| 멀티파트 파서의 이름 정리 | P0 검증 | 런타임 파서가 경로 등을 정리할 수 있으므로 JS File 생성만으로 우회 테스트를 끝내지 않고 raw multipart도 보낸다. |
| SPA 라우팅이 API 오류를 가림 | P0 검증 | 없는 `/api/*`가 index.html 200이 되지 않는지 확인한다. |
| 배포 성공과 리소스 준비의 차이 | P0 검증 | 빌드/배포만 통과해도 원격 D1 migration·R2 binding이 없으면 실패. 배포 URL에서 읽기/쓰기/저장을 확인한다. |
| 면접일까지 가용성 | P0 운영 확인 | 유지 기간·접속 점검 날짜를 실제 면접 일정에 맞춰 기록. 자동 감시는 요청받지 않았으므로 생성하지 않는다. |

최종 회고에는 계획 대비 구현·제외가 바뀐 항목과 실제로 남은 위험을 적는다. 검증 결과 없이 ‘안전한 업로드 완성’으로 단정하지 않는다.
