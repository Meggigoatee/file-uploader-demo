# 로그인 없는 세션별 정책 분리 방안 검토

- 기록 시각: 2026-10-23 19:52:08 KST, 도구 확인 시각. 사용자 전송 시각 미제공.

## 사용자 원문

> 지금 구성은 시작 시 고정확장자 체크 상태 등이 초기화 된 상태가 아닐 수 있는 우려가 있다.
> 다른 사용자의 설정 변경이 서로 영향을 주지 않도록, 로그인 없이 세션별로 정책을 분리하는 방안을 검토해줘.

## AI 중간 응답

“로그인 없이 접속별 정책을 분리하는 방안을 검토하겠습니다. 초기 체크 상태와 새로고침 유지, 다른 탭·브라우저 간 격리, 업로드 시 서버 정책 적용까지 함께 살펴보겠습니다.”

“현재 DB는 기존 체크 상태를 보존하므로, 다른 방문자가 변경한 값이 다음 방문자의 초기 화면에도 나타날 수 있습니다. 우선 권고안은 서버가 발급하는 익명 세션 쿠키로 정책을 분리하는 방식입니다. 다만 같은 브라우저의 탭끼리는 쿠키를 공유하므로, 탭마다 독립된 체험이 필요한 경우도 대안으로 비교하겠습니다.”

## 도구·검토·범위

- functions.exec/exec_command/rg로 DESIGN/PLAN/CONSIDERATIONS/TDD_PLAN/브레인스토밍, 기존 서버·클라이언트 API/업로드 코드·migration과 공유 타입을 읽었다. 전역 PK·보존 seed·세션 조건 없는 CRUD·업로드 정책 조회·전체 예산 singleton을 근거로 현재 문제를 확인했다. clock으로 시각을 확인했다.
- web 도구로 MDN의 Set-Cookie/sessionStorage와 Cloudflare 공식 D1 batch 문서를 확인했다. 세션 쿠키 복원 가능성·탭별 저장소의 opener 복사·HttpOnly의 fetch/XHR 전송·batch 원자성을 검토안에 반영했다. 검색에 나온 제3자 게시물은 설계 근거로 채택하지 않았다.
- apply_patch로 SESSION_POLICY_REVIEW와 관련 PLAN/DECISIONS/README·대화/PROMPT_LOG/VALIDATION을 기록했다. 새 문서의 최초 제목에 들어간 잘못된 언어는 한국어로 정정했다.
- 사용자 요청은 검토다. 익명 쿠키+D1를 권고하고 탭별 토큰 대안을 비교했다. 서버24시간 만료·새 데모 시작 UI·정리/발급 상한은 미확정 AI 제안이며 사용자 승인으로 기록하지 않는다.
- 정책만의 독립과 실제 사용자 식별·전체 자원 독립을 구분한다. 같은 쿠키 저장소의 탭은 같은 세션이며 전역 업로드 예산은 유지하는 안이다. 브라우저 종료를 확실한 초기화 시점으로 보장하지 않는다.
- 제품 코드·SQL·로컬 데이터·쿠키·화면을 변경하거나 실제 세션 검증/앱 테스트·배포를 수행하지 않았다. 따라서 Worker/UI 도메인 스킬은 아직 적용하지 않았고, 구현 시 해당 스킬을 적용할 로컬 TDD 검증 후보만 정리했다. 새 라이브러리·플러그인·서브에이전트·커밋/푸시 없음.

## 최종 사용자 응답

우려가 맞습니다. 현재는 기존 DB 값을 유지하므로 새 방문자도 다른 사람이 변경한 체크 상태로 시작할 수 있습니다. **서버가 발급하는 익명 세션 쿠키와 세션별 D1 정책을 사용하는 방식을 권장합니다.**

권고하는 동작은 다음과 같습니다.

| 상황 | 정책 상태 |
| --- | --- |
| 새 익명 세션 첫 접속 | 고정 7개 모두 체크 해제, 커스텀 0개 |
| 같은 세션에서 새로고침 | 본인이 변경한 정책 유지 |
| 다른 브라우저·프로필에서 접속 | 독립된 초기 정책 |
| 같은 브라우저의 다른 탭 | 같은 세션·정책 공유 |

서버는 정책 조회·수정뿐 아니라 **실제 업로드 검사에도 해당 세션의 DB 정책을 적용**해야 합니다. DB 키를 `(세션 ID, 확장자)`로 바꾸고, 커스텀 200개 제한도 세션별로 계산하는 구조입니다. 기존 Vue/Workers/D1 구성으로 구현할 수 있습니다.

다만 **새 탭마다 독립된 체험**이 필요하다면 쿠키 대신 `sessionStorage`에 세션 토큰을 두는 방식이 적합합니다. 이 경우 모든 API·업로드 요청에 토큰을 전달해야 하고, opener가 있는 새 탭의 저장소 복사도 처리해야 합니다. [MDN 설명](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage)

초기 상태를 확실하게 보장하려면 ‘브라우저를 닫으면 초기화’에 의존하기보다 **서버 만료 시간과 ‘새 데모 시작’ 동작**을 정하는 편이 좋습니다. 브라우저 복원 기능은 세션 쿠키도 복원할 수 있습니다. 이 수명과 버튼은 추가 제안입니다. [쿠키 수명 설명](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie#expiresdate)

앱 전체 저장 예산은 공유로 유지하는 것이 좋습니다. 새 세션을 만들 때마다 예산이 초기화되면 전체 저장 한도를 우회할 수 있기 때문입니다.

[상세 검토안](../SESSION_POLICY_REVIEW.md)에 변경 범위와 로컬 검증 항목을 정리했습니다. 현재는 검토 단계이며 구현·배포 전입니다.
