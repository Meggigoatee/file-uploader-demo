# 업로드 UI 상태 검증

이 저장소에서 파일별 상태와 서버 결과가 일치하는지 확인한다. 실제 화면·테스트 구현은 해당 사용자 요청의 범위 안에서 진행한다.

## 변경한 흐름에 맞춰 확인

[UI_UX](../../../.docs/UI_UX.md)의 해당 상태·상호작용과 [VALIDATION](../../../.docs/VALIDATION.md)의 관련 V 항목을 선택한다. 서버의 판정 의미가 관련되면 [DECISIONS](../../../.docs/DECISIONS.md)를 확인한다.

- 파일 선택/드롭이 같은 목록과 사전 검사를 사용하는지 확인한다. 목록 초과·제외·같은 이름의 파일을 포함한다(V26/V27/V30/V38).
- 전송 100% 뒤 서버 응답을 보류하고 화면이 서버 확인 중인지 관찰한 다음, 저장 성공 응답 이후에만 완료가 되는지 확인한다(V28). 전송 이벤트나 임의 대기 시간만으로 저장을 판정하지 않는다.
- 실제 저장 뒤 응답을 잃는 경우를 별도로 재현한다. 화면은 완료 확인 실패이며 성공 항목은 유지하고 재시도는 사용자가 시작해야 한다(V21/V32/V36). 무조건 요청을 abort한 결과로 이미 저장됐다고 가정하지 않는다.
- 정책 GET은 현재 정책·재시도 가능 여부만 갱신해야 한다. 진행 중/완료 결과나 과거 실패 사유가 새 정책으로 뒤집히지 않는지 확인한다(V34/V39).
- 정책 저장/그룹 전송 중 잠금, 최초 조회 실패·전송 직전 GET 실패·전체 장애 중단을 관찰한다(V18/V22/V40). 서버/DB 정합성 자체는 uploader-worker-checks의 실제 바인딩 검증과 연결한다.

## 실행과 증거

현재 Vue 3.5.41/Playwright 1.64.1/Chromium을 재사용한다. 기본 흐름은 실제 로컬 Worker와 연결하고, 응답 유실·지연처럼 필요한 경우에만 범위가 좁은 네트워크 제어를 사용한다. 모든 API를 mock한 결과는 통합 검증으로 기록하지 않는다.

접근 가능한 이름·역할로 요소를 찾고 웹 상태 assertion으로 기다린다. sleep이나 스크린샷 한 장을 동작 증거로 삼지 않는다. 실패 시 필요한 trace를 남기되 자동 재시도로 최초 실패를 감추지 않는다.

앱 E2E 구성 후 `pnpm exec playwright test ...`로 필요한 흐름만 실행한다. 전체 진입점·구성 부재 처리·증거 위치는 [하네스 문서](../../../.docs/HARNESS.md)를 따른다. 환경의 브라우저 기동 확인을 앱 E2E 통과로 표시하지 않는다.

실행 명령·관찰한 상태 전이·관련 V 항목·실패/미실행을 VALIDATION에 기록한다. 앱에 없는 기능이나 테스트를 검증을 위해 임의로 확장하지 않는다.

출처: 이 프로젝트의 UI_UX/DECISIONS/VALIDATION을 바탕으로 직접 작성했다. 실행·대기 근거는 [Playwright CLI](https://playwright.dev/docs/test-cli), [Playwright assertions](https://playwright.dev/docs/test-assertions) 공식 문서이며 외부 스킬을 복사·설치한 것이 아니다.
