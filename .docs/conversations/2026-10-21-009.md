# 대화 009 — 기술 기준안 선택과 UI/UX 설계

- 날짜/시간대: 2026-10-21, Asia/Seoul.
- 최초 시각 확인: 22:42 KST. 실제 사용자 전송 시각 미제공.
- 단계: 논의 사항의 계획·설계 반영, 화면/상호작용 설계. 코드 구현 요청 없음.

## 사용자 입력 원문

```text
현재 요구사항에 적합하면서 구성 및 구동이 단순하다면 그 쪽으로 결정하는게 옳지. 지금까지 논의 사항을 설계 및 계획 문서에 반영한다.

다음으로는 UI/UX 를 설계한다. 구현 요구사항이 화면에 어떻게 표시되고, 사용자가 어떤 방식으로 상호작용할지에 대한 문서를 새로 만들어서 작성한다. 필수/핵심 추가 기능/시간이 허용하면 가능한 옵션 항목으로 각각 분리하여 어떻게 화면을 구성할지 작성해라.
```

## 입력 의도

요구 적합성과 구성·구동 단순성을 기준으로 기술을 결정하고 지금까지 합의한 범위를 계획·설계에 반영한다. 다음 단계로 필수/핵심/조건부 옵션별 화면 구성과 사용자 조작을 별도 문서로 작성한다. 구현 권한은 여전히 부여하지 않았다.

## AI 중간 응답

> 현재 요구사항과 단순한 운영 구성을 기준으로 D1 사용안을 확정해 계획·설계 문서에 반영하겠습니다. 이어서 필수 기능, 핵심 추가 기능, 시간 여유 시 옵션을 구분한 UI/UX 설계 문서를 새로 작성하겠습니다. 화면 구성과 상태·상호작용을 설계하며, UI 코드는 작성하지 않겠습니다.

> 화면은 정책 관리와 파일 업로드를 한 페이지에 배치하고, 좁은 화면에서는 세로로 이어지도록 설계했습니다. 전송률 100% 이후의 서버 저장 확인, 완료 여부가 불명확한 실패, 수동 재시도를 구분했습니다. 이제 이 화면 흐름을 계획·기술 설계·검증 항목과 맞추고 있습니다.

> 필수 기능, 합의한 핵심 추가 기능, 시간 여유 시 옵션을 나눠 화면과 조작을 문서화했습니다. 카테고리 필터와 일괄 변경은 옵션으로 유지하고, 대표 확장자 안내는 기본 화면에 포함했습니다. 문서 간 기능 분류와 링크를 점검하고 이번 대화·AI 활용 기록을 남기겠습니다.

## 자료·도구와 판단 기록

- Codex 에이전트: 기존 합의를 UI 요소·상태·조작으로 구체화하고, 제안 출처/합의 여부를 보존했다.
- exec_command/PowerShell/rg: 원본 요건·기존 계획·설계·결정·기록 형식 확인, 문서 분류/링크 점검. clock.curr_time: KST 기록 시각 확인.
- apply_patch: UI_UX 신설, PLAN/DESIGN/DECISIONS/FEATURE_BRAINSTORM/VALIDATION/README 및 대화·프롬프트 기록 갱신. functions.exec: 도구 호출 실행.
- 기술 결정: Vue 3 Composition API + TypeScript + Vite / Workers + D1 + 비공개 R2를 기준안으로 선택. 사용자 결정 기준에 따른 선택이며 실제 계정·리소스·성능 검증 완료로 확대하지 않음.
- UI 세부안: 한 페이지의 정책/업로드 두 열과 좁은 화면 세로 배치, 추가 입력창을 통한 등록 확인, 대표 사전의 입력 보조, 대기 목록·순차 전송·상태별 결과/수동 재시도. 이 배치·문구·한도 값은 AI 설계안이며 사용자 원문 제안으로 바꾸어 기록하지 않음.
- 오류/경쟁: 같은 화면의 그룹 전송 중 정책/목록 변경 잠금, 시작/수동 재시도 전 정책 GET, 파일별 거절과 전체 장애의 지속/중단 구분, 서버 T 판정 유지, 응답 유실을 성공/미저장으로 추정하지 않음.
- 검토 중 보완: 기존 DESIGN의 ‘정규화 값만 20자’ 기준은 과제 입력 상한과 UI가 어긋날 여지가 있어 원문/정규화 값 모두 최대 20자로 명확히 했다. 기존 단일 파일 기준 분 단위 일정을 현재 합의 기능을 포함한 실행 순서/통과 조건으로 교체했다. 새 추정 시간을 임의로 만들지 않음.
- 옵션: 카테고리 조회 필터·대표 목록 일괄 변경만 시간 여유 시 검토. 시그니처·상태 조회·멱등성·SHA-256·빈도 제한 등 미채택 대안을 옵션으로 자동 승격하지 않음.
- 회고: 등록/차단, 전송 완료/저장 완료, 과거 결과/현재 재시도 가능 여부를 화면에서 구분했다. 필수 기능과 UX 추가 기능의 출처를 유지하며, 오류 복구가 새 작업 상태 서버로 확장되지 않도록 제한했다.
- 새 스킬·플러그인·서브에이전트·웹 조사 없음. 코드·설정·SQL·설치·계정/리소스·배포 변경 없음. 실제 UI 렌더링·앱 테스트·성능/시간 실측은 미실행.
- 문서 점검 결과(22:59 KST): Markdown 19개, 코드 블록 제외 로컬 링크 45개(앵커 포함), 깨진 링크 0개, `.docs` 밖 파일 0개. UI 표 필수 7행·핵심 11행·조건부 옵션 2행 확인. 실제 화면/앱 테스트 결과와 구분한다.
