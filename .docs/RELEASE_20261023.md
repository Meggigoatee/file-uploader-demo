# 2026-10-23 배포와 최종 운영 검증 — RELEASE-20261023

사용자 최신 요청으로 검증된 세션/카테고리 변경을 커밋하고 origin에 푸시한 뒤 Cloudflare에 배포한다. 부하·대량 파일 업로드는 수행하지 않는다. 기존 최종 로컬 기준은 단위65/Worker57/E2E29=151개·타입/빌드 통과다.

## 실행 순서와 환경 통과 조건

1. Git 변경 범위/비밀값/로컬 데이터 제외, 원격 이력과 인증·D1/R2 존재·원격 migration 목록을 읽기 확인한다. 검증 스크립트와 문서도 커밋에 포함한다.
2. 커밋/정상 fast-forward push 후 승인된 migration3~5를 적용하고 기존 예산/정책을 보존한다. 검증한 번들을 해당 Worker에 배포한다.
3. 현재 배포 버전/100% 활성화·DB/UPLOADS 바인딩, D1 migration/필요 스키마·정책/예산 불변식, R2 존재/비공개, HTTPS HTML과 실제 배포 JS/CSS 응답을 확인한다. 실패하면 분석/수정 후 환경을 다시 확인하며 기능 검증을 시작하지 않는다.
4. 환경 통과 결과를 JSON에 저장한 뒤에만 순차 기능 검증을 허용한다. 브라우저 A/B 두 세션과 작은 파일을 사용해 새 기본값/한쪽 변경 격리·새로고침 유지, 카테고리 생성/이름/소속 편집/필터/일괄·개별 정책·삭제, 서버 차단/허용을 확인한다.
5. 운영 업로드 성공은 최대2개·파일당128바이트 이하로 제한한다. 차단 요청도 소수의 작은 파일만 사용한다. 각 실제 객체를 원격 R2에서 읽어 바이트/해시 일치를 확인하고 이번 객체만 삭제한다. 이번 테스트 세션만 D1에서 정리하며 앱 누적 예산은 환급/초기화하지 않는다.
6. 실행·실패·해결·커밋/배포 버전·저장 증거를 VALIDATION/TDD_LOG와 이 문서에 기록하고 결과 문서도 커밋/푸시한다. 기능/정책/요건을 바꾸지 않는다.
