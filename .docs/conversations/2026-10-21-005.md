# 대화 005 — A/B 시간 추정의 근거

- 날짜/시간대: 2026-10-21, Asia/Seoul.
- 최초 시각 확인: 21:46 KST. 실제 사용자 전송 시각은 제공되지 않음.
- 단계: 추정의 근거·한계 검토. 코드 구현 요청 없음.

## 사용자 입력 원문

```text
A, B 안의 소요 시간 추정은 어떤걸 기준으로 나온것이지?
```

## 입력 의도

AI가 제시한 A 70~110분/B 90~140분의 산정 근거를 확인한다. 기능 채택·폐기나 구현 요청으로 해석하지 않는다.

## AI 중간 응답

> 문서에 적은 작업별 추정과 그 근거를 확인하겠습니다. 실측이나 자료에서 확인한 사실과 제 판단으로 산정한 부분을 구분해 설명하고, 이번 대화도 기록하겠습니다.

## 확인 및 정정

- 산정은 작업별 직관적 시간 배분의 합계였다. 실측·벤치마크·생산성 보정·통계적 범위 근거가 없었다.
- 공통 API/화면 재사용, 단순 UI, 정상 도구 환경을 가정했다. 실제로 구현은 아직 없다.
- 구현자·AI/사용자 역할·검토/대기·반복 수정 시간을 일관되게 정의하지 않았다.
- MDN은 API 확인 자료이며 시간 추정 자료가 아니다. 산술 합계 확인도 추정의 정확성을 뒷받침하지 않는다.
- FEATURE_BRAINSTORM의 ‘구현 경험에 근거’ 표현을 정정하고 ‘미검증 초기 추정/신뢰도 낮음’으로 표시. 시간 수치에 따른 기능 선택·6시간 가능 여부 판단은 보류한다.
- 사용자 질문을 계기로 AI 제안의 근거가 약함을 명시했다. 새로운 시간 수치를 만들어 대체하지 않는다.
- 원래 응답과 이전 프롬프트 기록은 당시 기록으로 보존한다. 최종 합의 기능은 계속 없음.

## 도구 사용

- exec_command/PowerShell: 비교 문서, 프롬프트 기록, 문서 목록 확인.
- clock.curr_time: KST 기준 시각 확인.
- apply_patch: 비교 문서의 추정 근거·한계 정정 및 대화/AI 활용 기록 작성.
- 신규 웹 검색·스킬·서브에이전트·패키지 설치·앱 코드·테스트·배포 없음.
- 문서 점검 결과: Markdown 13개, 코드 블록을 제외한 로컬 링크 23개(앵커 포함), 깨진 링크 0개, `.docs` 밖 파일 0개. 이는 시간 추정이나 앱 동작의 검증이 아니다.
