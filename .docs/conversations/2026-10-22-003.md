## AI 중간 응답

> 합의된 범위와 현재 검증 계획을 바탕으로 구현 순서와 핵심 테스트를 정리하겠습니다. TDD 루프마다 실패 원인, 최소 구현, 리팩토링, 회귀 확인을 기록하는 절차를 계획에 반영하고, 실제 코드는 계획 승인 후 시작하겠습니다.

> `uploader-worker-checks`와 `uploader-ui-checks`의 검증 기준을 계획에 적용하겠습니다. 실제 DB·저장 검증을 먼저 확보한 뒤 화면과 연결하고, 각 TDD 루프에서 새 동작의 실패·통과뿐 아니라 이미 완성된 기능의 회귀 결과도 남기도록 구성하겠습니다.

> 구현 순서는 최소 실행 구성 → 공유 검증 규칙 → 정책 DB/API → 실제 업로드·저장 → 정책 화면 → 다중 업로드 UX → 통합 회귀로 잡았습니다. 동시 등록 상한, 정책 판정 시점 T, 저장 후 응답 유실을 핵심 테스트에 포함하고, V01~V40 검증 항목을 각 단계에 연결하겠습니다.

> 핵심 테스트를 19개 묶음으로 정리했고, 카테고리 필터·일괄 변경은 기존처럼 조건부 옵션으로 남겼습니다. 매 루프의 리팩토링 뒤에는 대상 테스트와 누적 회귀 검사를 수행하도록 했습니다. 현재는 계획과 기록 양식만 작성 중이며 앱 테스트 파일이나 설정은 변경하지 않았습니다.

> 계획 문서와 TDD 기록 양식을 작성했고, 작업 지침에도 ‘계획 승인 후 구현 시작’을 반영했습니다. 마지막으로 검증 항목 누락과 문서 링크를 확인하고, 패키지·하네스·스킬 파일이 그대로 유지됐는지 점검하겠습니다.
