# 대화 008 — SQLite/D1 선택 이유

- 날짜/시간대: 2026-10-21, Asia/Seoul.
- 최초 시각 확인: 22:31 KST. 실제 사용자 전송 시각 미제공.
- 단계: 기술 선택 근거 설명. 구현 요청·DB 선택 승인/변경 지시 없음.

## 사용자 입력 원문

```text
네가 선택한 기술 중 sqlite 가 있다. mysql, postgresql 등 rdbms 도 있는데 sqlite 를 선택한 이유가 뭐지?
```

## 입력 의도

SQLite 선택의 근거와 다른 RDBMS 대비 타당성을 묻는다. 엔진과 배포 서비스를 구분하고 현재 과제의 요구·배포 제약과 연결해 설명한다.

## AI 중간 응답

> SQLite 선택을 Cloudflare D1 배포안과 연결해 설명하겠습니다. 아직 기술 구성이 확정된 것은 아니므로, MySQL·PostgreSQL과의 차이와 이 과제에서의 선택 근거를 확인하고 문서에도 남기겠습니다.

## 자료·도구와 판단 기록

- exec_command/PowerShell: 현 DESIGN의 기술 제안·관련 기록 확인. clock.curr_time: KST 기준 시각 확인.
- web.run: Cloudflare D1 소개/바인딩/동시성 한도, Hyperdrive의 PostgreSQL/MySQL 지원, SQLite 공식 적합 사례 확인. 최종 비교의 배포 비용·도입 부담 판단은 AI의 추론이며 실측이 아님.
- apply_patch: DESIGN의 DB 선택 이유와 DECISIONS의 상세 근거·한계 보강, 대화/프롬프트 기록 및 README 목록 갱신.
- 설명: SQLite도 RDBMS. 제안은 Worker 로컬 파일 DB가 아니라 SQLite SQL semantics의 관리형 D1. 작은 정책/예산 모델, 짧은 원자적 쓰기, Cloudflare 바인딩 연동을 근거로 제안.
- MySQL/PostgreSQL 관리형 서비스와 Hyperdrive도 가능하며 Cloudflare가 D1만 허용한다고 하지 않음. D1의 직렬 쿼리/오버로드와 예산 단일 행 경합을 명시. 기존 사용자 DB 숙련도·계정이 알려지지 않았음을 반영.
- 기술 구성은 제안 유지. 성능/시간/비용의 우위를 실측했다고 하지 않으며 사용자의 질문을 DB 승인으로 기록하지 않음.
- 코드·설정·SQL·라이브러리 설치·계정/리소스·배포 변경 없음. 스킬·서브에이전트 없음.
- 문서 점검: Markdown 17개, 코드 블록을 제외한 로컬 링크 34개(앵커 포함), 깨진 링크 0개, `.docs` 밖 파일 0개. 앱 동작·성능·시간 실측은 미실행이다.

## AI 최종 응답

```markdown
가장 큰 이유는 **Cloudflare 배포와 6시간이라는 범위에서 DB 연결·운영 설정을 줄이기 위해서**입니다.

정확히는 **SQLite 문법을 사용하는 관리형 DB인 Cloudflare D1**을 제안했습니다. SQLite도 RDBMS이며, Worker 안에 SQLite 파일을 직접 저장하는 구성은 아닙니다. ([D1 소개](https://developers.cloudflare.com/d1/))

선택 근거는 세 가지입니다.

1. **배포 구성이 단순해집니다.** Workers에서 D1 바인딩으로 접근하므로 외부 DB 제공자와 연결 설정을 추가하는 범위를 줄일 수 있습니다.
2. **현재 데이터 모델에 충분합니다.** 정책 최대 207행과 예산 1행을 저장하고 파일은 R2에 둡니다. 주요 작업도 조회·단건 변경·조건부 갱신입니다.
3. **필요한 정합성 처리가 가능합니다.** 고유 제약과 원자적 갱신으로 중복 등록, 200개 상한, 저장 예산을 관리할 수 있습니다. 실제 동시 요청 검증은 별도로 해야 합니다.

한계도 있습니다. **D1 단일 DB는 쿼리를 한 번에 하나씩 처리**하므로, 동시 업로드가 많아지면 예산 갱신 등이 병목이 될 수 있습니다. 그때는 DB와 예산 관리 모델을 함께 재검토해야 합니다. ([D1 동시성](https://developers.cloudflare.com/d1/platform/limits/#concurrency-and-throughput))

MySQL·PostgreSQL도 Cloudflare에서 사용할 수 있습니다. Hyperdrive가 두 DB를 지원합니다. 이미 익숙하고 준비된 DB 환경이 있거나 많은 동시 쓰기·복잡한 트랜잭션이 요구된다면 그쪽을 선택할 이유가 충분합니다. ([지원 DB](https://developers.cloudflare.com/hyperdrive/reference/supported-databases-and-features/))

현재 D1 제안은 **이 과제의 배포 구성과 작은 데이터 모델에 맞춘 판단**입니다. 성능·개발 시간·비용이 더 낫다는 실측 결과는 없으며, 기술 선택도 아직 확정하지 않았습니다.
```
