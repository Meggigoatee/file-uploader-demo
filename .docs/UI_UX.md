# 화면 구성과 사용자 상호작용 설계

기준 설계일: 2026-10-21. 2026-10-22 핵심 UI와 2026-10-23 세션별 정책을 구현했다. 2026-10-23 후속 지시로 6절의 카테고리 필터·일괄 변경과 사용자 카테고리를 로컬 구현했다. 실제 결과·미검증 항목은 VALIDATION을 따른다. 카테고리 변경은 배포하지 않았다.

## 1. 설계 기준과 범위 구분

- **필수:** 원본 과제가 반드시 요구한 정책 관리·실제 업로드 기능.
- **핵심 추가:** 사용자/AI 제안 중 합의한 UX·품질 보완. 기본 완성 화면에 포함한다.
- **후속 확정 기능:** 이전 시간 여유 옵션이던 카테고리 조회 필터·일괄 차단/해제와 사용자 카테고리는 2026-10-23 명시적 요청으로 구현한다. 완료 목록 일괄 정리는 여전히 미합의다.
- 문서의 분류와 기능 ID는 개발/검증용이다. 실제 화면에 ‘필수/추가 과제’나 AI·DB 제품 이름을 노출할 필요는 없다.
- 정책 편집은 확인창 없이 즉시 저장한다. 업로드 성공은 서버의 저장 완료 응답을 확인한 뒤 표시한다.
- 단일 페이지에 정책 설정과 업로드를 함께 배치한다. 로그인·탭 전환·별도 관리 페이지·파일 보관함은 추가하지 않는다.

## 2. 전체 화면

2026-10-22 후속 사용자 요청에 따라 모든 화면 폭에서 **파일 업로드 → 차단 정책** 순서의 상하 한 열로 배치한다. 추가/등록 확인은 별도 입력으로 분리하고 정책 조회 버튼은 ‘정책 새로고침’으로 표시한다. 아래는 최신 배치다.

```text
파일 업로드 정책 관리
익명 세션 데모: 정책은 현재 브라우저 세션에 저장되며 새로고침해도 유지됩니다.

파일 업로드 · 파일당 최대 5 MiB / 목록 최대 10개
[ 파일을 여기에 놓거나 파일 선택 ]
전송 목록 3/10
report.txt   전송 가능       [업로드] [제거]
program.exe  사전 차단       [업로드(비활성)] [제거]
notes.pdf    완료 확인 실패  [재시도] [제거]
[업로드 시작 (1)] [실패 파일 재시도 (1)]

확장자 차단 정책                  [정책 새로고침]
고정 확장자 □ bat □ cmd □ com □ cpl □ exe □ scr □ js
커스텀 추가 [예: pdf       ] 0/20 [추가]
입력 검증/중복 안내
커스텀 차단 2/200 [sh ×] [zip ×]
등록 여부 확인 [확인할 확장자 입력]
현재 등록 여부/차단 상태 안내
자주 쓰는 확장자 안내
사진: [jpg] [jpeg] [png] [webp] [gif]
영상: [mp4] [webm] [mov] [avi] [mkv]
음성: [mp3] [wav] [ogg] [flac] [aac]
문서: [pdf] [txt] [docx] [xlsx] [pptx]
개별 항목은 고정과 같은 체크박스입니다. 체크=차단, 체크 해제=허용.
카테고리 이름 오른쪽에 차단 수량, 우측 상단에 [+][×]를 표시합니다.
[전체 차단/전체 허용] 단일 버튼은 현재 소속 전체에 적용합니다.
```

선택·전송 목록은 이번 브라우저 화면의 상태이다. 성공 파일의 서버 보관함으로 표현하지 않는다. 새로고침하면 정책은 DB에서 복구하고 파일 목록/결과는 초기화한다. 파일을 다시 선택해야 한다는 점을 목록 아래 짧게 안내한다.

### 정책 입력·목록 세부 규칙

1. 입력과 서버 모두 **원문 최대 20자**를 지킨다. 붙여넣기 초과는 조용히 잘라 등록하지 않고 오류로 알린다. 입력된 기존 값은 보존한다.
2. 앞뒤 공백·선행 점 1개 제거·ASCII 소문자 변환 후 영문/숫자 1~20자를 검증한다. 예: `.PDF`는 `pdf`로 저장됨을 안내한다. 내부 점/공백·특수문자·유니코드 확장자는 허용하지 않는다.
3. 추가 성공 시 입력을 비우고 새 태그가 보이도록 한다. 실패 시 값과 포커스를 유지한다. 목록은 이름순으로 정렬한다.
4. 커스텀은 등록 자체가 차단이다. 태그마다 별도 체크박스를 만들지 않는다. 최대 200개를 줄바꿈으로 보여주고 영역에 적절한 최대 높이/스크롤을 둔다. 가상 스크롤·페이지네이션은 사용하지 않는다.
5. 수량은 서버에 저장된 전체 커스텀 수이다. 요청 중인 추가/삭제를 미리 수량에 포함하지 않는다. 빈 목록은 ‘등록된 커스텀 확장자가 없습니다.’라고 표시한다.

### 등록 여부 확인과 대표 분류

- 별도 등록 확인 입력의 `pdf`가 커스텀에 있으면 ‘이미 커스텀 차단 목록에 등록되어 있습니다.’를 보여주고 해당 태그를 강조한다. 추가 입력의 중복 검사도 독립적으로 유지해 중복 추가를 막는다.
- 등록 확인 입력의 `exe`가 고정이면 ‘고정 확장자 · 현재 차단/해제’를 표시한다. ‘등록됨’이 곧 ‘차단 중’이라고 표시하지 않는다.
- 등록 확인에서 미등록이면 ‘등록된 확장자가 없습니다.’를 표시하며 DB를 쓰지 않는다. 추가 입력은 유효한 값/정책 조회 완료/200개 미만이면 추가할 수 있고 서버도 중복을 다시 검사한다.
- 대표 사전은 검색 결과와 독립적인 작은 정적 목록이다. 이미지·영상·음성·문서의 위 예시 13개를 기본안으로 사용한다. 알려지지 않은 값은 ‘기타’이다. 분류는 파일 내용의 실제 형식을 보증하지 않는다.
- 카테고리 개별 항목은 고정 확장자와 같은 체크박스를 사용하며 체크/해제 시 정책을 저장한다. 소속 추가/제거만으로 차단 상태를 바꾸지 않는다. 별도 커스텀 추가/등록 확인 입력은 서로 독립이다. 전체 버튼의 명시적 클릭만 전체 정책을 변경한다.

### 선택·드롭·대기 목록

1. 정책 조회 성공 후 파일을 선택/드롭할 수 있다. 폴더·URL·문자열은 파일 목록에 넣지 않고 지원 범위를 안내한다.
2. 기존 목록을 유지하며 선택 순서로 추가한다. 취소한 파일 선택 창은 목록을 바꾸지 않는다. 같은 파일명도 다른 행으로 취급하며 자동 내용 중복 제거는 추가하지 않는다.
3. 기본 한도 10개는 성공/실패를 포함해 현재 화면에 남아 있는 전체 목록에 적용한다. 남은 슬롯보다 많은 묶음은 전체 추가를 거절하고 ‘현재 8/10개입니다. 2개까지 추가할 수 있습니다.’처럼 알린다. 일부만 조용히 넣지 않는다.
4. 파일명/크기와 정책을 확인해 전송 대기 또는 사전 차단으로 표시한다. ‘전송 가능’은 악성코드/실제 내용 검증 통과를 뜻하지 않는다.
5. 처리 시작 전 ‘목록에서 제거’로 제외한다. 완료/실패 행도 목록에서 제거할 수 있으며 이 조작은 서버 파일 삭제가 아니다. 전송 그룹 처리 중에는 목록 변경을 잠근다.
6. ‘업로드 시작 (N)’은 아직 보내지 않은 전송 가능 항목만 보낸다. 시작/수동 재시도 직전에 정책을 한 번 재조회하고 해당 대상의 사전 판정을 갱신한다. 재조회 실패면 전송을 시작하지 않는다. 사전 차단 행은 목록에 남기고 전송하지 않는다. 전송할 항목이 없으면 버튼을 비활성화하고 이유를 표시한다.
7. 기본은 한 파일당 한 요청, 순차 전송이다. 실패 파일 재시도는 별도 수동 동작이며 성공 파일은 다시 보내지 않는다. 갱신된 정책으로 허용되어도 과거 실패를 자동 재전송하지 않는다.
8. 행별 ‘업로드’를 ‘제거’ 왼쪽에 같은 크기로 둔다. 그 행 하나만 기존 정책 재조회/잠금 경로로 전송한다. 사전 차단·진행 중·완료 행은 업로드 비활성, 실패 행은 같은 자리에 기존 ‘재시도’를 유지한다.
9. 완료 목록 정리는 사용자 의견 요청 상태다. AI는 성공 행만 수동 ‘완료 항목 비우기’를 권고했다. 승인 전에는 자동 정리나 일괄 비우기를 구현하지 않으며 기존 결과를 유지한다.

| 사전 차단 | ‘exe 확장자가 차단되어 있습니다.’ | 제거 또는 정책 변경 후 재확인. 이 상태로 전송하지 않음 |
| 전송 중 | ‘전송 중 43%’ | 해당 행의 제거/재시도 비활성 |
| 전송률 계산 불가 | ‘전송 중’과 불확정 진행 표시 | 숫자 진행률을 추정해 만들지 않음 |
| 서버 확인 중 | ‘전송 완료 · 서버 확인 중’ | 성공/실패 응답 대기. 100%로 성공 확정하지 않음 |
| 업로드 완료 | ‘업로드 완료’ | 결과 유지·목록에서 제거. 재시도 대상 제외 |
| 서버 거절 | ‘서버 정책에서 exe가 차단되었습니다.’ | 이전 실패 사유 유지, 현재 정책 재확인 후 재시도 가능 여부 결정 |
| 업로드 실패 | ‘업로드를 완료하지 못했습니다.’ | 실패 이유에 따라 수동 재시도. 성공/미저장을 추정하지 않음 |
| 완료 확인 실패 | ‘완료를 확인하지 못했습니다. 다시 업로드해 주세요.’ | 수동 재시도. 이미 저장됐을 수 있고 재시도 시 중복 가능함을 행에 안내 |

재시도 버튼은 직전 실패를 확인하고 다시 시도할 의사를 표현하는 동작이다. 상태 조회 API·자동 복구·자동 재전송은 사용하지 않는다. 실패 행의 이전 결과와 현재 전송 가능 여부를 구분해 표시하며, 새 시도가 시작되면 해당 행의 진행 상태를 갱신한다.

## 5. 화면 전체의 로딩·오류·잠금

| 화면 상황 | 화면 표시와 가능한 조작 |
| --- | --- |
| 최초 정책 로딩 | 정책 영역에 로딩, 정책 변경/파일 등록/업로드 비활성 |
| 최초 조회 실패 | ‘정책을 불러오지 못했습니다.’와 ‘다시 불러오기’. 빈 차단 목록으로 업로드를 허용하지 않음 |
| 정책 저장 중 | 해당 상태 표시, 중복 정책 변경과 업로드 시작 잠금. 기존 목록·파일 유지 |
| 정책 저장 명확한 실패 | 이전 확정 값 복구, 입력 유지, 오류와 재시도 안내 |
| 정책 저장 응답 유실 | ‘저장 결과를 확인하지 못했습니다.’와 재조회. 정책/업로드 변경 잠금, GET 성공 후 해제 |
| 파일 전송 그룹 처리 중 | 파일 추가·제거·재시도·정책 변경 잠금. 검색/대표 안내 조회는 가능 |
| 파일별 정책/검증 거절 | 해당 행에 이유 표시. 정책을 재조회해 다음 대기 항목을 확인하고 가능한 항목은 이어서 처리 |
| 네트워크·DB·저장소 사용 불가 | 현재 행 실패/확인 실패, 다음 요청 시작 중단. 남은 대기 항목 유지. 사용자가 문제 해소 후 다시 시작 |
| 누적 업로드 예산 소진 | ‘데모 업로드 한도가 소진되어 현재 업로드할 수 없습니다.’. 전송/재시도 중단, 정책 조회와 목록/결과 유지 |

한도는 시간만 기다리거나 새로고침한다고 자동 초기화되지 않는다. UI에서 정확한 무료 잔량/남은 저장량을 계산해 표시하는 새 대시보드나 조회 API는 추가하지 않는다.

같은 화면에서는 그룹 전송 중 정책 변경을 잠가 혼선을 줄인다. 같은 익명 쿠키를 공유하는 탭의 변경은 가능하며 다른 세션은 독립이다. 서버 최종 검증 시점 T 전 같은 세션 변경은 반영하고 T 이후 변경은 다음 업로드에 적용한다. 정책 재조회로 성공한 행을 실패로 뒤집지 않는다. 화면 안내는 ‘서버 검사 이후의 정책 변경은 다음 업로드에 적용됩니다.’로 표현할 수 있다.

2026-10-23 CATEGORY-04 수정: 제거 모드에서는 체크박스를 렌더하지 않고 같은 테두리 안에 `확장자 이름 ×`를 표시한다. ×는 텍스트 바로 오른쪽에 놓는다. 일반 모드로 돌아가면 기존 공통 체크박스를 표시한다. 소속 제외와 현재 차단 정책의 구분은 유지한다.

2026-10-23 CATEGORY-05 수정: 커스텀 차단 목록의 `확장자 ×`도 카테고리 제거 칩과 같은 테두리·크기·여백·× 스타일을 사용한다. 등록 여부 확인의 강조 표시는 유지한다. 커스텀의×는 차단 해제, 카테고리의×는 소속 제외라는 기존 동작은 유지한다.

### 일괄 변경과 사용자 카테고리

- 고정된 ‘5종’ 버튼명을 사용하지 않는다. 모든 현재 구성원을 대상으로 하는 ‘전체 차단/전체 허용’ 단일 버튼을 사용한다. 수량은 카테고리 이름 바로 옆에 붙인다.
- 상태는 실제 정책에서 대표 목록 중 차단된 개수를 계산한다. 별도 카테고리 boolean을 저장하지 않는다. 일부만 차단되면 ‘4종 중 2종 차단’을 표시한다.
- 이미 등록된 값은 중복 추가하지 않는다. 고정 항목이 대상이면 고정 체크 값만 변경하고 커스텀으로 옮기지 않는다.
- 해제는 대표 목록에 속한 수동 등록 항목에도 적용하는 최소안을 사용한다. ‘직접 등록한 해당 확장자도 해제됩니다.’를 버튼 근처에 안내한다. 등록 출처/과거 상태 복원은 구현하지 않는다.
- 상한 초과/저장 오류면 전체 적용을 거절하고 이전 상태를 유지한다. 처리 중 정책 변경·업로드 시작을 잠근다. 응답 유실이면 결과를 추정하지 않고 정책 새로고침 전까지 잠근다. 재조회 완료 후 오래된 오류 안내를 지운다.
- 생성/이름 변경은 별도 팝업의 이름1~30자 입력만 받는다. 소속은 상단+의 단일 확장자 입력으로 추가한다(원문20자·최대50개). 같은 카테고리 중복은 추가를 막고, 다른 분류/정책에 이미 등록됐으면 현재 상태와 함께 안내한다. 소속 제거 모드는 항목 옆×로 분류에서만 제외하며 차단은 유지한다.
- 사용자 카테고리 자체 삭제는 확인 팝업으로 소속 모두 허용을 알리고 취소할 수 있다. native dialog로 배경 조작/포커스를 제한하고 Escape/취소 시 돌아간다. 저장 중 닫기/확인을 잠그며 응답 유실 후 닫아도 재조회 안내와 정책 잠금을 유지한다.
- 기타 필터는 어느 기본/사용자 카테고리에도 속하지 않은 등록 확장자다. 선택한 카테고리가 삭제되면 전체로 돌아간다. 사용자 카테고리와 정책은 같은 익명 세션에서 유지한다.

시그니처 검사, 상태 조회·멱등성, SHA-256, 빈도 제한, 취소/재개, 자동 재시도, 미리보기·다운로드·서버 파일 보관함은 이번 화면의 시간 여유 옵션으로 승격하지 않는다. 기존 생략/보류/대안 상태를 유지한다.

## 7. 기본 가독성과 접근성

- 체크박스·입력·파일 선택·추가·제거·시작·재시도는 이름이 있는 실제 입력/버튼으로 표현한다. X에는 ‘sh 차단 해제’처럼 항목과 의미를 포함한 접근 가능한 이름을 준다.
- 키보드로 모든 기본 조작이 가능하고 포커스가 보이게 한다. 저장/오류 상태는 색상만으로 전달하지 않는다.
- 입력 오류는 필드 옆, 파일 실패는 해당 행, 전체 장애는 영역 상단에 둔다. 결과 메시지는 보조 기술에서도 알 수 있게 하되 진행률 변화를 지나치게 반복 낭독하지 않는다.
- 작은 화면에서 태그는 줄바꿈하고 파일 행은 카드처럼 세로 배치한다. 긴 파일명은 줄바꿈해 확인 가능하게 하며 상태/버튼이 밀려나지 않게 한다.
- 저장된 목록에서 항목을 삭제한 뒤 다음 조작 가능한 항목 또는 입력창으로 포커스를 유지한다. 모달·복잡한 메뉴·애니메이션·별도 UI 프레임워크는 요구하지 않는다.

## 8. 대표 사용자 흐름과 검토 기준

1. exe 체크 → 저장 확인 → 새로고침 → 체크 유지. 추가 확인창 없음.
2. 입력창에 `PDF` → 등록 여부 확인 → 미등록이면 추가 → `pdf` 태그/수량 표시. 다시 입력하면 중복 안내/추가 중단.
3. 사진 카테고리의 `png` 체크 → 정책 차단 저장. + 팝업은 소속만 추가하고 × 제거 모드는 소속만 제외. ‘전체 차단/전체 허용’은 모든 현재 소속 정책 변경.
4. txt/차단 exe/pdf를 함께 선택 또는 드롭 → 각 행의 예상 결과 확인 → 불필요한 행 제거 → 전송 가능 파일만 시작.
5. txt는 성공, pdf는 응답 유실 → txt 성공 유지, pdf는 완료 확인 실패 → 사용자가 실패 파일만 재시도. 성공 파일 재전송 없음.
6. 서버 검증 T 전 정책 변경으로 거절 / T 후 변경 중 저장 완료 / 성공 뒤 현재 정책 재조회가 각각 합의한 판정과 일치.
7. 네트워크 실패·한도 소진·초기 조회 실패에도 입력/선택 목록을 잃거나 성공으로 잘못 표시하지 않음. 한도 초과 요청은 서버도 거절.
8. 옵션을 구현했다면 필터가 DB를 바꾸지 않고 일괄 변경의 상한·실패·현재 상태가 화면과 일치.

검증 ID와 실제 실행 결과는 [VALIDATION.md](./VALIDATION.md)에 연결한다. 이 문서는 화면/상호작용 설계이며 실제 UI 동작을 검증한 결과가 아니다.
